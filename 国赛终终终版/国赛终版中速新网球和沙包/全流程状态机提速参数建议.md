# 全流程状态机提速参数清单与推荐值

> 核对日期：2026-08-18  
> 源码范围：根目录 `base.py`、`task_leader.py`、`task_follow.py`、`config.py`。  
> 本文只做代码分析和调参建议，没有修改任何运行参数。`leader/`、`follower/` 是构建产物，不应直接编辑。

## 1. 结论先行

当前最适合的提速顺序是：

1. 先统一 `PUSH_ROUTE` 主从速度。当前主车 `_PUSH_ROUTE_SPEED=80`，从车为 `120`，与源码注释中“两车必须相等”的设计约束冲突。
2. 先提无接触移动：`BOOT_SYNC`、`SEARCH`、`RECOVER`、`RELOCALIZE`、`DONE`。
3. 再提目标附近移动：`APPROACH/FACE`、`ORBIT`、`CLOSE/VDOCK`。
4. 最后提有物体接触的普通 `PUSH` 和斜避障。

本文“推荐值”是一套偏稳妥的第一轮提速值，整体大多提高约 10%～20%，不是底盘极限值。建议一次只改一个大状态，实车验证后再进入下一组。

### 1.1 单位说明

- 平移速度使用工程内部“底盘速度单位”。虽然很多位置和距离以 cm 表示，但源码没有把所有速度严格标定为 cm/s，因此本文不把速度单位写成 cm/s。
- 固定旋转速度变量以 `DPS` 命名，单位为度/秒。
- `KP` 把位置误差转换为速度；`MAX` 是该修正通道的速度限幅；`TOTAL_MAX` 是多个前馈/反馈合成后的总速度限幅。
- `request_pos(..., speed, ...)` 中的 `speed` 只是位置模式的最大速度，接近目标后仍会由位置 P/D 环自动减速。

### 1.2 最重要的风险点

| 优先级 | 问题 | 当前情况 | 建议 |
| --- | --- | --- | --- |
| P0 | ROUTE 主从速度不一致 | 主车 `_PUSH_ROUTE_SPEED=80`；从车 `=120` | 第一轮统一为 `100`；验证稳定后可一起试 `110` |
| P0 | 提速后停车距离增长 | 公共 `_VEL_DECEL_RATE=700` | 随无接触状态提速同步改为 `850`；若翘头明显则退回 `750～800` |
| P1 | SEARCH 从车纠偏余量 | 主车横扫提高后，从车前馈和纠偏更容易撞到 `_FOLLOWER_SEARCH_TOTAL_MAX=240` | 主车横扫改 `120` 时，从车总限幅同步改 `260` |
| P1 | PUSH 是接触动作 | 普通 PUSH 已经是主从 `120`，且网球不能退出普通 PUSH | 第一轮只升到 `135`，不要直接跳到 `150+` |
| P1 | DONE 自转已经很快 | 主车 `_DONE_SPIN_RATE_DPS=540` | 不再提高 |

## 2. 公共底盘速度链路（所有状态都会受影响）

文件：`base.py`

| 参数 | 当前值 | 推荐值 | 含义与影响 |
| --- | ---: | ---: | --- |
| `_VEL_DECEL_RATE` | `700.0` | `850.0` | `WORLD/HOLD` 模式的世界速度减速率。速度提高而该值不变时，停车距离会同步变长。只影响软停车，不影响 `request_hard_hold()`。 |
| `_VEL_ACCEL_RATE` | `0.0` | `0.0` | `0` 表示起步不做公共加速斜坡。第一轮先保持，避免所有状态的起步节拍一起改变；若提速后明显打滑，可单独试 `900.0`。 |
| `_VEL_RAMP_MIN_SPEED` | `40.0` | `40.0` | 低于该合速度直接归零，不走缓停。保持不变，避免影响 CLOSE/VDOCK 等低速精定位。 |
| `_POS_X_KP` / `_POS_Y_KP` | `2 / 2` | `2 / 2` | `request_pos` 的位置比例增益。提速第一轮只抬调用方的速度上限，不先动位置环增益。 |
| `_POS_X_KD` / `_POS_Y_KD` | 主从均 `0.4 / 0.4` | 保持 | 位置环阻尼。提高最大速度后先观察到点过冲，再决定是否提高到 `0.5`。 |
| `_ANGLE_KP/_KI/_KD` | `110/0/20` | 保持 | 普通目标航向角度环，影响所有 `request_world/request_pos/request_hold` 转向。不要和各状态的平移速度同时改。 |
| `_MOTOR_PWM_DUTY_SPEED_PID_MAX` | `10000` | 保持 | 速度环总 PWM 上限，已是满量程。提速不应继续增大。 |
| `_MOTOR_PWM_DUTY_SPEED_PID_INTEGRATE_MAX` | `3000` | 保持 | 每个 2 ms 电机周期允许累加的最大 PWM。过大容易冲击，第一轮不动。 |

### 公共控制的实际区别

- `request_world`：恒速命令，受公共加/减速斜坡影响。
- `request_pos`：位置环自动减速，不走 `_VEL_DECEL_RATE` 的世界速度斜坡。
- `request_hold`：软停车，受 `_VEL_DECEL_RATE` 影响。
- `request_hard_hold`：立即清平移目标和速度环积分，RECOVER、PUSH 完成等关键交接使用，不受软停车参数影响。
- `request_push`：使用 PUSH 自己的基座速度、视觉 PD 和 `SLEW`，不走公共世界速度斜坡。

## 3. BOOT_SYNC

两车都锁 `90°`，沿世界 `+Y` 横移，同时在世界 X 方向拉开前后间距。

| 文件/角色 | 参数 | 当前值 | 推荐值 | 含义 |
| --- | --- | ---: | ---: | --- |
| `base.py`，主从共用 | `_BOOT_LATERAL_SPEED` | `130` | `150` | 开局横移的主速度分量；是 BOOT 最直接的耗时参数。 |
| `base.py`，主从共用 | `_BOOT_LONGITUDINAL_SPEED` | `20` | `25` | 主车取正、从车取负，用于拉开两车前后距离。 |
| `base.py`，主车 | `_BOOT_LATERAL_DISTANCE_LEADER_CM` | `60` | `60` | 主车横移结束距离，不是速度参数，不建议为省时间而缩短。 |
| `base.py`，从车 | `_BOOT_LATERAL_DISTANCE_FOLLOWER_CM` | `70` | `70` | 从车横移结束距离，保持原几何。 |

推荐只把速度改为 `150/25`。若开局里程计打滑或从车进入 SEARCH 后追赶过多，先把横移速度退到 `140`，不要缩短距离。

## 6. WAIT_READY

WAIT_READY 正常动作是 `request_hold`，本身没有持续平移速度。它使用的移动速度都来自上一节的 ROUTE_BACK、重靠近 CLOSE/VDOCK。

| 参数 | 当前值 | 推荐值 | 含义 |

## 7. PUSH_SYNC

### 7.1 普通 PUSH_RUN

| 参数 | 主车当前 → 推荐 | 从车当前 → 推荐 | 含义 |

- `_PUSH_PID_LEADER_BY_OBJ`、`_PUSH_PID_FOLLOWER_BY_OBJ`：两车当前相同；网球/玩偶为 `(side_kp, side_kd, fwd_kp, fwd_kd)=(5,10,3,6)`，沙包为 `(9,18,4,10)`，保持当前值。

- `_PUSH_SIDE_MAX_LEADER`、`_PUSH_SIDE_MAX_FOLLOWER`：专用表无效时的兜底值均为 `50`，保持。
- `_PUSH_D_LPF_LEADER/_FOLLOWER=0.35`：D 项滤波，保持。
- `_PUSH_INWARD_BIAS_DEG_BY_OBJ`：推送方向内偏角，属于几何而不是速度，保持。

网球进入普通 PUSH 后即使视觉丢失也会继续推到正常离开黄线；因此网球提速必须最后单独验证，重点看斜避期间是否仍能保持夹持。

## 12. 每批参数的实车验收条件

### BOOT / SEARCH

- 主从均能完成开局横移，没有明显轮胎空转或位置跳变。
- 主车反向 sweep 时，从车不会因提前停车锁存而停在原地；能随反向速度解除锁存。
- 从车在两种横扫方向都不丢主车视野，`TRANSLATE` 横向/前后误差不会持续顶住限幅。
- 黄线修正后不会因停车距离变长再次冲出边界。

### APPROACH / WAIT_READY

- FACE 转向没有持续左右摆动。
- ORBIT 不扩圈、不切进目标内侧，不与另一车抢同一条路径。
- 主车 CLOSE、从车 VDOCK 到位后不会高速反复穿越误差带。
- ready 建立时间缩短，但没有因视觉单帧抖动频繁回 APPROACH。

### PUSH

- 主从普通基座速度必须相同，不能只改一台。
- 网球普通 PUSH、预避障、后续视觉斜避方向全程保持一致，丢视觉后仍能正常推出黄线并计数减一。
- 沙包/玩偶的前后修正不长期打满 `35`；如果长期打满，应先查两车真实轮速差，不应继续提高限幅。
- ROUTE 中两车接触稳定后再进入巡航，没有一台明显拖拽或顶开另一台。

### RECOVER / RELOCALIZE / DONE

- 8 cm BACK 不因惯性残速提前完成。
- 黄线坐标修正至少仍能稳定取得要求的连续帧数。
- 重定位斥力与主速度叠加后，单轴命令不要长期超过底盘可实现范围。
- DONE 的 `540°/s` 自转不丢累计角；若 IMU 积分漏圈，应降低而不是提高。

## 13. 调参时不要一起动的组合

- 不要同时提高 `_ORBIT_SPEED_MAX`、`_ORBIT_RUN_RADIAL_KP` 和 `_ORBIT_INWARD_FF_GAIN`。先提切向速度和径向限幅，保留增益。
- 不要同时提高普通 PUSH 基座速度和 PUSH PD 增益。先提基座速度、限幅和 `SLEW`，观察误差再调 PID。
- 不要同时提高 SEARCH 主车速度和前馈增益。先提高从车总限幅/纠偏限幅，前馈增益保持当前值。
- 不要把 `_RELOCALIZE_REPULSE_SPEED` 跟着主速度一起提高。它是直接叠加项，最坏情况下会把单轴命令推得过高。
- 不要为了节省时间直接缩短异常超时。正常动作应按距离、角度或视觉帧结束，超时只用于防卡死。

## 14. 建议记录的测试数据

每批调参至少分别测试两种横扫方向、四条推出边和五类物体，并记录：

- 每个大状态耗时：BOOT、SEARCH、APPROACH、WAIT_READY、PUSH、RECOVER、RELOCALIZE、DONE。
- 主从实际世界速度与目标速度，尤其是 PUSH 和 SEARCH 反向 sweep。
- 从车视觉 `rel_x/rel_y` 的峰值、稳态误差，以及各修正通道是否长期撞限幅。
- 电机 PWM/编码器是否饱和；若速度命令提高但实际速度不再增加，继续抬参数没有意义。
- 网球是否在普通推送或斜避方向切换处掉落。
- 每次黄线修正的触发帧数、修正完成时间和最终位置误差。

完成 A～D 四批后，再依据实际瓶颈做第二轮，而不是统一再乘一个比例。
