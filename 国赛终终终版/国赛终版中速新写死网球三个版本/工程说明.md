# 双车协同搬运工程说明

> 最后核对：2026-08-14。本文依据当前工作区的 `config.py`、`debug_switch.py`、`base.py`、`task_leader.py`、`task_follow.py`、`openart.py` 和 `build.bat` 重新核对，用于以后在新窗口中快速恢复工程上下文。开始修改前先读本文，再按任务打开对应源码；当本文、历史修改记录、源码注释和实际执行代码不一致时，以当前 `.py` 的常量与执行分支为准。

## 1. 工程概览

这是一个运行在逐飞/Seekfree 智能车平台上的双车协同搬运工程。两台全向麦轮车分为主车（leader）和从车（follower），各自配有 RT1021 一类的 MicroPython 主控及 OpenART 摄像头。主车负责搜索、选择目标、规划推送边和发出协同命令；从车通过无线同步目标，完成编队、夹持、跟推与恢复。

系统同时使用三类定位/观测：

- 四轮编码器里程计提供连续 X/Y；
- IMU 提供连续 yaw 以及 Roll/Pitch 姿态估计；
- OpenART 用黄线估算绝对边线位置/航向，用 YOLO 和颜色检测识别物体、另一台车、标记球、cone 及 brick。

正常任务主流程为：

```text
BOOT_SYNC
  -> SEARCH
  -> APPROACH
  -> WAIT_READY
  -> PUSH_SYNC
  -> RECOVER
  -> SEARCH（仍有目标）

全部目标完成后：
RECOVER -> RELOCALIZE -> DONE
```

异常时会在 `APPROACH`、`WAIT_READY`、`PUSH_SYNC` 等状态间回退、重靠近或返回 `SEARCH`，不能只按上面的直线流程理解。

## 3. 启动、构建与烧录

### 3.1 板端启动链

```text
main.py
  -> import base
  -> base.py 末尾 import task
  -> base.main_init()
       hw_init()
       state_init()
       apply_config()
       pit_start()
  -> base.loop()
       comm_update()
       task.update()
       debug_view_update()
```

烧录目录里任务模块固定叫 `task.mpy`。构建时脚本会临时把 `task_follow.py` 或 `task_leader.py` 重命名为 `task.py` 再编译，之后恢复原名。

### 3.2 构建命令

在 Windows 工作区根目录运行：

```bat
build.bat
```

脚本顺序为：

1. 把根目录 `config.py` 的 `_IS_LEADER` 改为 `0`，编译从车；
2. 清空并重建 `follower/` 内容；
3. 编译 `base.py`、`task_follow.py`、角色化 `config.py` 和 `debug_switch.py`，只复制 `main.py`；
4. 把 `_IS_LEADER` 改为 `1`，以同样方式生成 `leader/`；
5. 正常成功后，根目录 `config.py` 最终停在 `_IS_LEADER = 1`。

注意：构建会改写根目录 `config.py`、临时改名任务源码并覆盖两个输出目录。如果构建中途被强制打断，需要检查：

- 根目录是否残留 `task.py`；
- `task_leader.py` / `task_follow.py` 是否仍在；
- 根目录 `_IS_LEADER` 当前是什么；
- 两个生成目录的身份配置是否分别为主车 `1`、从车 `0`。

### 3.3 烧录边界

- RT1021 主车烧录 `leader/` 中全部文件。
- RT1021 从车烧录 `follower/` 中全部文件。
- `openart.py` 不在 `build.bat` 的输出范围内，需要单独烧到 OpenART。
- OpenART 还依赖 SD 卡模型 `/sd/yolo3_iou_smartcar_final_with_post_processing.tflite`。
- OpenART 的 `CAR_ID=1` 表示无黄色胶带的主车配置，`CAR_ID=2` 表示有黄色胶带的从车配置；当前根目录 `openart.py` 是 `CAR_ID = 1`。烧到从车前必须改为 `2`，并确认单应矩阵、车体屏幕原点和推杆偏移随角色切换。

## 4. 软件分层与数据流

```text
OpenART 摄像头
  黄线 / YOLO / 色块球 / cone
        |
        | Frame2（UART3, 230400）
        v
base.py 通信与融合层 <---- Frame3（UART2, 230400）----> 另一台车
  IMU + 编码器
  视觉位置修正
  对方状态镜像
        |
        v
task_leader.py / task_follow.py
  大状态机 + 子状态机 + 协同决策
        |
        | request_world / request_pos / request_hold / request_push
        v
base.py 运动控制层
  世界系速度 -> 车体系 -> 麦轮解算 -> 速度/角度/角速度 PID -> 电机
        |
        +---- Frame1（UART3, 230400）----> OpenART（位姿、识别开关、目标约束）
```

关键分层约定：

- `task_*.py` 不直接控制电机，只向 `base.py` 提交运动请求。
- `base.py` 只保存对方数据到 `_Other_*` 镜像，任务层决定是否采用。
- 大量控制状态为模块级变量，这是为了适配 MicroPython 内存和实时性；新增容器、闭包和临时分配要谨慎。
- `micropython.const` 的下划线常量存在编译期可见性陷阱：在函数之后才定义、却被前面的函数引用，可能在 MicroPython 上变成 `NameError`。相关常量应放在首次引用之前。

## 5. 坐标、角度、类别和哨兵值

### 5.1 坐标约定

- 世界场地标称大小为 `310 cm × 230 cm`，中心约 `(155, 115)`。
- 车体系相对坐标使用 `rel_x` 表示横向、`rel_y` 表示前向。
- 车体系到世界系转换为：

```text
world_x = car_x + cos(yaw) * rel_x + sin(yaw) * rel_y
world_y = car_y - sin(yaw) * rel_x + cos(yaw) * rel_y
```

- yaw 以度表示并归一化到 `[0, 360)`；代码里的 0°、90°、180°、270°对应场地正交方向。
- 推送边到基础推送方向：边 1 → `0°`（高 Y），边 2 → `270°`（低 X），边 3 → `90°`（高 X），边 4 → `180°`（低 Y）。
- 主车初始位置由 `config._LEADER_INIT_POS` 配置，当前为 `(40,-40)`；从车由 `config._FOLLOWER_INIT_POS` 配置，当前为 `(10,-40)`。两车初始世界航向统一固定为 `base._INIT_YAW=90°`，不再放在配置中。DONE 返回点统一由 `config._DONE_TARGET_POS` 配置，当前两车都是 `(25,-50)`。

### 5.2 目标类别

| ID | 含义 | 默认推送边 |
| ---: | --- | ---: |
| 0 | 另一台车 | 不搬运 |
| 1 | 网球 tennis | 1 |
| 2 | 蓝沙包 blue_sandbag | 2 |
| 3 | 红沙包 red_sandbag | 2 |
| 4 | 白色玩偶 white_teddy | 3 |
| 5 | 棕色玩偶 brown_teddy | 3 |
| 6 | 主车左/紫色标记球 | 辅助编队 |
| 7 | 主车右/橙色标记球 | 辅助编队 |
| 8 | cone | 障碍物 |
| 9 | brick | PUSH 路障对象，与 cone 共用斜推避障 |
| 255 | 无效视觉槽 | 无 |

数量配置有三种模式：

- `_OBJ_COUNT_MODE = 1`：只知道总数，使用 `_OBJ_UNKNOWN_TOTAL`；当前备用值为 `3`。每成功推出一个目标总剩余数减 1，允许重复类别；
- `_OBJ_COUNT_MODE = 2`：按类别组计数，使用 `_OBJ_GROUPS/_OBJ_GROUP_TOTAL`。当前备用组为 `(1)`、`(2,3)`、`(4,5)`，每组需要完成 1 个，即“网球 1 个、任一颜色沙包 1 个、任一颜色玩偶 1 个”，共 3 个目标。同组完成任一成员后，该组其他类别也会被禁用；
- `_OBJ_COUNT_MODE = 3`：按五个类别分别计数，使用 `_OBJ_CLASS_TOTAL`。当前为 `(0,1,1,1,1,1)`，即网球、蓝沙包、红沙包、白熊、棕熊各成功推出 1 个，某一类不能替代另一类。

当前实际运行模式为 `_OBJ_COUNT_MODE=3`，总任务数为 5。Frame1 线上只有 1 bit 数量模式：控制器模式 2 和模式 3 都编码为视觉端模式 0，并通过剩余类别 bit mask 过滤；控制器模式 1 编码为视觉端模式 1，只看总剩余数。模式 3 的每类具体剩余数量只保存在主控任务层，视觉端只需要知道该类是否仍可选择。

目标边始终按 `task_leader._OBJ_PUSH_EDGE=(0,1,2,2,3,3)` 的源码固定映射选择；该表已从 `config.py` 移出。原先按成功搬运次数在边1/边2之间交替的预赛模式及 `_OBJ_EDGE_MODE` 已删除。从车直接使用主车无线下发的目标边。

### 5.3 无效值

工程大量使用 `999.0` / `999.9` 表示无效坐标、无效角度、无命令或数据尚未收到。判断通常使用 `< 900.0`。不要把合法值、默认值或协议扩展值设计到 900 附近。

## 6. 主任务状态机

大状态编号主从一致：

| 编号 | 模式 | 作用 |
| ---: | --- | --- |
| 1 | `BOOT_SYNC` | 等摄像头、无线和双方启动握手 |
| 12 | `SEARCH` | 主车扫描选目标；从车在主车后方编队跟随 |
| 13 | `APPROACH` | 两车绕目标分到推送方向两侧并贴近 |
| 14 | `WAIT_READY` | 双方确认就位和目标状态；推送走廊检查与路线换阵当前开启 |
| 15 | `PUSH_SYNC` | 双车同步夹推、丢目标恢复；cone/brick 与其他货物斜推当前开启 |
| 16 | `RECOVER` | 推出后撤离边界/目标区域 |
| 17 | `DONE` | 返回各自起点并保持 |
| 19 | `RELOCALIZE` | 全部目标完成后的边线重定位和防撞收尾 |

### 6.1 BOOT_SYNC

两车先确认 OpenART 和无线链路。主车通过命令子状态发送启动并蜂鸣提示；主车和从车随后都锁定 `90°` 航向，以世界 `+Y=130` 为横移主分量，并叠加共用幅值 `_BOOT_LONGITUDINAL_SPEED=20` 的车体前后分量：主车前进，对应世界速度 `(20,130)`；从车后退，对应世界速度 `(-20,130)`。两车各自记录本车横移起点，主车以自身 `Position_Y` 正向增量达到 `60 cm` 作为进入 SEARCH 的条件，从车则要求达到 `70 cm`；叠加的世界 X 分量不参与结束判定。从车收到主车 `BOOT_START` 后才启动，不会提前进入 SEARCH 跟随主车。

横移完成后：

- 主车按自己的里程计完成 60 cm 后进入 SEARCH，从车按自己的里程计完成 70 cm 后进入 SEARCH；从车若漏收最初的 `BOOT_START`，可由新鲜的主车 SEARCH 模式或 `BOOT_SEARCH_SWEEP` 兜底启动横移，但仍必须完成本车 70 cm 后才切入 SEARCH；
- 主车只在第一次进入 SEARCH 时执行 `_SEARCH_FIRST_DIAG`：进入状态时根据当前位置到目标点 `(120,55)` 的向量只计算一次方向，将合速度 `150` 归一化分配为固定世界 `vx/vy`，之后不再追点，车头保持 `90°`；X/Y 任一有效轴沿初始运动方向达到目标值即结束。随后进入 `_SEARCH_FIRST_TURN_YAW` 原地锁到 `0°`，稳定 `100 ms` 后进入 `_SEARCH_FIRST_STRAIGHT`，以速度 `80` 持续向前搜索网球；
- 从车完成自身横移后才执行正常 `ORBIT_FORM -> TRANSLATE_FORM` 编队流程；若从车先完成而主车仍在 BOOT 横移，可临时把主车 BOOT 模式视为合法跟随对象，主车进入 SEARCH 后自动恢复正常对端模式限制；
- 主车只在确认从车的新鲜模式为 SEARCH 之前持续发送 `BOOT_SEARCH_SWEEP`。首次斜移和原地转向期间均禁止锁物；进入 `_SEARCH_FIRST_STRAIGHT` 且从车 SEARCH 模式已同步后，才允许锁定网球并进入 APPROACH。

### 6.2 SEARCH

主车：

- 首轮不再使用可选航向，固定为 `0°` 网球直搜。车辆上电姿态、BOOT 横移和首次固定斜移仍保持 `90°`，斜移结束后才原地转到 `0°`。
- 首次进入 SEARCH 时先执行 `_SEARCH_FIRST_DIAG`，斜移和转向期间不锁定物体。达到 `(120,55)` 对应目标线后进入 `_SEARCH_FIRST_TURN_YAW`：主车以零平移原地转到 `0°`，航向误差进入 `±6°` 并连续稳定 `100 ms` 后进入 `_SEARCH_FIRST_STRAIGHT`。该状态以世界速度 `(vx,vy)=(0,80)` 持续前进，没有搜索超时、坐标边界、黄线修正或障碍换行出口；只有锁定网球才进入 APPROACH。该一次性标志在首次 SEARCH 初始化时就消耗，后续从 APPROACH、RECOVER 等状态重新进入 SEARCH 不会再次跑这条直搜线。
- 当前扫描为固定正交车头下的蛇形轨迹：以速度 `120` 做无前向偏置的纯横移；到横向边界后沿车头方向以速度 `120` 前进最多 `30 cm`，然后停车等从车重新到位，再反向横移。第一次、每次换行后、黄线修坐标后、RECOVER 返回 SEARCH 后及最后一行反向时，每次 Sweep 前都经过同一个等待握手。
- 前进轴不足 `30 cm` 时只走到搜索区域边界；到达前进轴尽头后留在最后一行继续往返横扫，直到锁物或SEARCH总超时。
- 主车SWEEP纯横扫；本机视觉cone/brick满足当前横扫侧 `0<有向rel_x<=50 cm`、`0<rel_y<50 cm` 时锁存世界坐标并提前进入STEP。`rel_y<50 cm` 用于屏蔽相机远处看到的其他边障碍。STEP以速度 `120` 前进，同时沿下一次反向SWEEP方向叠加 `min(3×(60-锁存障碍距离),168)` 的退让速度；障碍离开视野后锁存持续到STEP结束，STEP最长 `3000 ms`。RELOCALIZE继续使用独立四槽、`3000 ms`记忆和 `50 cm`触发，最大避障速度为`150`且方向固定为世界`-Y`。
- SWEEP 因视觉障碍提前进入 STEP 时蜂鸣器短响一次；STEP 中只有实际退让速度大于0时才保持高电平长鸣，停止刷新超过 `200 ms` 自动停响。正常到达搜索坐标边界进入 STEP，以及锁存障碍仍在斥力触发距离外时不响。
- `config._OBSTACLE_LAYOUT_FILTER_ENABLE=0` 时上述 SEARCH 及 PUSH cone/brick 入口保持旧视觉逻辑；设为 `1` 后按 `_OBSTACLE_EDGE_LAYOUT` 的四边三位置和 `_OBSTACLE_CORNER_LAYOUT` 的四角先验过滤。SEARCH按当前横扫边和沿边三等分位置筛选，端部区段同时考虑对应角点；PUSH按整条目标边及其两个角点筛选。未在对应范围声明的障碍类型即使被本车或从车视觉识别，也不会触发这两处避障。
- OpenART 自由选物只考虑车体系直线距离不超过 `60 cm` 的可搬运目标，并在候选中选择最近者；不再按推送边与 SEARCH yaw 的角差排序，也没有固定时长观察窗。最近候选需保持同类别且相邻位置不超过 `30 cm`，连续 `2` 个模型推理帧后才发布。首帧确认期间普通 slot0 以 `class_id=255、track_id=254` 标记“有候选、尚未发布”。YOLO 置信度门槛为 `0.75`。
- OpenART 发布目标后，主控任务层当前要求同一类别有效识别 `1` 帧即可正式锁定。
- 主车锁定后直接进入 APPROACH，不再停车等待从车第二次上报 SEARCH 阵列稳定。从车在 SEARCH 中收到 `1` 帧主车已经处于 APPROACH/WAIT_READY 且目标有效的新鲜数据后，跟进 APPROACH。
- 未锁定目标时，主车从进入普通 `_SEARCH_SWEEP` 后累计达到 `config._SEARCH_TIMEOUT_MS`（当前 `16000 ms`）转 RELOCALIZE；黄线补坐标和每次 Sweep 前等从车的时间都会补回计时器，不占用扫描超时。
- `_SEARCH_MOVE_TO_POINT` 的速度为 `140`、最长运行时间为 `3000 ms`。正常 RECOVER 后转到 SEARCH 航向时不再调用 `request_hold()`，转向完成的当个控制周期直接开始恒速到线移动；越过目标搜索线后进入 `_SEARCH_FORMATION_WAIT` 停车等从车，再开始横扫。
- 四条推出边对应的下一条搜索线分别为：边 1 后 `y=180`、边 2 后 `x=100`、边 3 后 `x=210`、边 4 后 `y=60`；SEARCH 航向取刚才推送方向的反方向。注意源码注释中“边3回到220”的文字已落后，实际执行常量是 `210`。
- 仅在正常 `RECOVER -> SEARCH` 后，主车会把第一次横扫相对 `_search_yaw` 的左右方向通过 Frame3 `flags.bit4~5` 持续发给从车。编码为 `0=无效、1=左、2=右、3=保留`；信号从第一次 S3 编队等待开始，覆盖完整个第一次 Sweep 和紧随其后的第一次 Forward，在 Forward 完成、主车重新进入 S3 时清零。若已在最后一条搜索线而没有 Forward，则在第一次 Sweep 结束时清零。开局首次 SEARCH、异常回退和本轮后续 Sweep 均发送无效。
- `_SEARCH_FIRST_STRAIGHT`、`_SEARCH_SWEEP` 和 `_SEARCH_STEP_FORWARD` 允许累计和锁定物体；`_SEARCH_FIRST_DIAG` 和 `_SEARCH_FIRST_TURN_YAW` 不锁物。首次直搜由首目标类别掩码只开放网球，其他类别不能打断该路线。
- `_SEARCH_SWEEP` 中若连续收到靠近画面中心、且与当前横扫方向同侧的黄色线矩形框，主车会执行一次 `LINE_STOP -> LINE_TURN -> LINE_POS_FIX -> LINE_TURN_BACK`：向左横扫时只允许左线触发，向右横扫时只允许右线触发；随后按矩形中心左右方向转 90°，只打开横扫轴对应的 X/Y 视觉修正，再转回原 `_search_yaw`。
- 黄色线中心使用原始 `0～320` 像素，减 160 后取符号；连续 2 个新帧满足 `0<abs(line_x)<130` 且与横扫方向同侧才触发，黄线无效或 `abs(line_x)>150` 解除区域锁存。触发时立即锁存左右方向，转向过程中不再改变。
- 每次进入 SEARCH 最多执行一次黄线补坐标；触发即占用本次机会，即使转向或修正超时也不会再次尝试，退出并重新进入 SEARCH 才重置。
- 补坐标后不裁剪真实坐标，而是依据所见边界强制把 `_search_sweep_sign` 设为朝场内；坐标瞬间落到正常 SEARCH 范围之外时也不会继续向场外行驶。

从车：

- 视觉看见主车时，绕到主车目标航向的后方槽位，并用距离、方位、主车世界速度前馈共同控制。
- 正常 SEARCH 后方距离为 `25 cm`；主车无线世界速度先转换到从车车体系：S1/ORBIT 使用左右/前后 `1.0/1.0` 前馈，S5 平移跟随主车 Sweep/Forward 使用 `1.15/1.0`，随后再转换回世界速度；合速度上限 `240`，无线位置单独跟随速度为 `160`，无线位置/速度新鲜期为 `500 ms`。RELOCALIZE 跟随另用 `30 cm` 和 `1.1` 倍速度前馈。
- 正常 SEARCH 的 ORBIT 粗绕速度为 `80`、精调和越过回调速度为 `75`；剩余角度进入 `35°` 后开始线性减速，方位误差小于 `20°` 即认为进入目标槽位。
- 普通 SEARCH 当前路径为 `ORBIT_FORM → REAR_YAW_ALIGN → TRANSLATE_FORM → ready=2`。ORBIT 先用主从世界坐标确认从车到达主车正后方：横向坐标误差必须不超过 `_FOLLOWER_SEARCH_WORLD_REAR_LAT_EPS=6 cm`，同时主车沿 `_search_yaw` 正前方领先从车的有向距离必须严格大于 `_FOLLOWER_SEARCH_WORLD_REAR_FWD_MIN=15 cm`；到位后硬停车并锁存位置，再在 `REAR_YAW_ALIGN` 中单独原地转到 `_search_yaw`，之后进入 TRANSLATE 平移跟随。位置一旦锁存，短暂视觉/无线波动不会让它退回 ORBIT；RELOCALIZE 则使用独立的简化视觉跟车，不复用这套编队状态机。
- ORBIT 进入 TRANSLATE 要求主车仍在前方、绕行方位误差 `<20°`、画面方位误差 `<=20°`、航向误差 `<=10°`。平时不依赖主车等待状态，交接周期保留主车速度前馈并直接锁定 `_search_yaw`，开局 BOOT 横移和首次斜移期间也能连续切换。
- TRANSLATE 同时锁航向并修正车体系横向/前向误差，前后都叠加主车速度前馈；前馈在从车车体系左右/前后轴分别乘 `1.15/1.0`。横向 Kp/限幅/死区为 `6/70/7 cm`；前向太近后退和太远追赶增益均为 `7`，前进与后退共用限幅 `80`，前向死区为 `7 cm`。死区淡入倍数为 `1.5`，最终仍受合速度 `240` 限制。
- 主车仍处于 SEARCH `S4` 横扫时，从车 S5 使用自身世界坐标在主车搜索边界内缩 `15 cm` 处提前锁住当前横扫轴：X 轴阈值为 `115/205 cm`，Y 轴阈值为 `75/165 cm`。锁存作用在前馈与反馈合成后的最终世界速度上，只清零横扫轴；主车进入 `S6` 换行或 `S3` 等待、退出 SEARCH、无线状态超过 `500 ms` 未更新，或者从车退出 S5 时立即解除。
- LCD第96/112像素行分别显示当前视觉帧的cone与brick相对坐标 `C rx/ry`、`B rx/ry`，无有效观测时显示 `--`，用于调试SEARCH的50/50 cm触发窗。
- TRANSLATE 首次上报 `ready=2` 的严格条件为横向误差 `±7 cm`、前向误差 `±7 cm`、航向误差 `±6°`，连续稳定 `200 ms`。已经 ready 且主车正处于 SEARCH `S3` 等待时，释放阈值放宽为横向/前向 `±10 cm`、航向 `±8°`，避免单帧抖动撤销握手；超出释放阈值后清为 `ready=0`，但仍留在 TRANSLATE 平移纠偏。主车每次进入 SEARCH `S3` 等待时，从车都会强制开始一次新的 ready 握手。
- RECOVER 后第一次 S3 握手中，从车一收到有效的两位 Sweep 方向，就直接把临时 `_search_yaw` 设为 `_search_normal_yaw ± 90°`，立即复用 `ORBIT_FORM -> REAR_YAW_ALIGN -> TRANSLATE_FORM` 到达该侧向航向对应的主车正后方；侧向阵型稳定后才发送 `ready=2`，主车随后开始第一次 Sweep。不再执行旧 `S6 LOOK_TURN -> S7 LOOK_HOLD -> S8 RETURN`，也不再读取相机新帧或按 cone/brick 分有障碍/无障碍两条路线。
- 从车在第一次 Sweep 和第一次 Forward 中始终保持上述侧向 `_search_yaw` 与对应后方阵型，因此期间主车锁定目标进入 APPROACH 时，从车仍以稳定的相对 `±90°` 姿态交给侧向入场规划器。Forward 完成后主车清零方向并进入 S3；从车这时才恢复 `_search_normal_yaw`、重新执行普通 ORBIT/REAR_YAW_ALIGN/TRANSLATE，完成后以 `ready=2` 放行第二次 Sweep。最后一条搜索线没有 Forward 时，在第一次 Sweep 结束后执行同样恢复。
- TRANSLATE 中普通横向和前后距离误差不再触发回绕，无论是否已经锁存都持续由平移反馈修正。只有画面方位误差 `>60°` 或主车跑到从车后方，任一异常持续 `200 ms` 才直接退回 ORBIT，不在交接处额外停车。
- 视觉丢失但无线位姿新鲜时，先清除编队锁存并按无线坐标跟随主车后方点，视觉恢复后从 ORBIT 重新建立几何；视觉与无线坐标同时失效时，进入从车 `S3` 并以 `90°/s` 原地自转找主车。
- 从车可利用“主车无线世界坐标 + 画面中的主车相对坐标”反算自身坐标，正常最短间隔 `500 ms`；RECOVER 后还会挂一次不受该周期限制的强制修正请求。

### 6.3 APPROACH

- 推送方向两侧候选角通常为 `push_yaw ± 45°`。
- 主车在自身 FACE 完成、准备进入 ORBIT 时比较主从车实时偏航角。若两车近似同向，继续使用原规划器；若从车相对主车保持 `+90°/-90°`（允许 `±30°` 误差），则把主车当前 yaw 作为相对 `0°`、把从车视作位于相对 `+90°/-90°` 的一侧，启用侧向入场规划。该判断只看相对角，主车绝对角可以是任意方向。
- 侧向入场规划按两个候选槽位相对主车的位置分三类：①槽位分列主车朝向两边时，主车取离从车虚拟 `±90°` 位置更远的槽并走最短方向，从车取另一槽并反向；②两个槽位都在从车同侧时，主车取离自己更远的槽并选择不经过从车虚拟位置的方向，从车取另一槽，但方向延迟到其真正到达 ORBIT 起点后再算；③两个槽位都在从车异侧时，主车同样取远槽并避开从车虚拟位置，从车取另一槽且与主车同向。
- 第二类中主车先保存从车槽位，但把主车/从车两个无线规划字段都保持为无效，防止从车通过兼容回退逻辑提前自行选向。主车自身仍可按已生成的槽位和方向运行；从车完成 FACE 和半径调整后先上报 `AP_ORBIT` 并停车。主车收到目标一致且不超过 `700 ms` 的新鲜 `AP_ORBIT` 后，以从车实时报头角为基础，并在世界坐标反算角与报头角相差不超过 `30°` 时优先采用反算角，计算从车到预分配槽位的贪心最短方向，再一次性发送有效的“槽位 yaw + ±1 方向”。
- 从车把 `AP_ORBIT` 作为“已到环绕起点”状态，而不是无条件起步指令。首次 ORBIT 运动前必须同时确认：主车处于 APPROACH/WAIT_READY、无线数据新鲜、目标 `edge/obj_id` 一致、当前目标槽位在 `0～359°`、方向为 `+1/-1`；任一条件不满足都保持当前偏航角停车。主车若已经完成自己的 CLOSE、但第二类从车方向仍未下发，也会继续留在 APPROACH 等待，不会提前切到 WAIT_READY。
- 从车由侧向 SEARCH 阵型进入 APPROACH 后，等主车进入 ORBIT 且两车航向拉开安全角度，再根据主车共享的物体世界坐标原地转向物体；进入 `±6°` 后锁存该航向，以车体前向速度 `40` 缓慢前进，直到本机看到目标，再无缝交给普通 FACE/ORBIT。普通 FACE 使用刚锁存的物体朝向，不再回用进入 APPROACH 时的侧向 `search_yaw`。
- 主车普通流程为 `FACE -> ORBIT -> CLOSE`；`PRE_ORBIT` 主要供路线重靠近等特殊入口使用，旧 `CENTER` 已删除。
- 从车主要经历 FACE、PRE_ORBIT/ORBIT、VDOCK；VDOCK 使用物体、标记球和无线关系形成紧 V 字夹持。
- 目标长时间丢失、对方回到 SEARCH、路线重靠近或 PUSH 丢目标恢复都可能让 APPROACH 从不同子状态重新进入。

### 6.4 WAIT_READY

- 双方检查目标是否仍可信、位置是否仍满足、对方状态是否新鲜。
- 当前 `config._READY_ROUTE_AVOID_ENABLE=1`，路线检查与 route-reclose 正式启用。主车和从车都会观察推送走廊中的其他待搬目标；确认挡路后，主车选择侧向带离轴并通过无线下发，双车先回到 APPROACH 重靠近、执行路线推送，再恢复正常阵列和 PUSH。关闭该开关时才退化为只检查目标可信度。
- 正常双方 ready 后进入 PUSH_SYNC。
- `debug_switch.READY_HOLD_ENABLE=1` 时会在这里停车，不进入推送；当前为 `0`。

### 6.5 PUSH_SYNC

- 主车是推送完成、丢目标和障碍路线的主要决策方；从车服从主车模式和命令。
- 主、从车基础推送速度当前均为 `150`。主车进入 PUSH 后总共保持 `100 ms`，并提前 `100 ms`（即进入延时分支时立即）广播 `ready=4`；从车收到 `ready>=4` 后起步，若未收到则最多等待 `1500 ms` 后兜底起步。
- 主、从车都启用了被推物体视觉 PUSH 闭环，并分别通过 `_PUSH_PID_LEADER_BY_OBJ`、`_PUSH_PID_FOLLOWER_BY_OBJ` 按 `obj_id` 配置。两车当前表值相同：网球、白熊、棕熊为 `(5,10,3,6)`，蓝、红沙包为 `(11,22,5,12)`，格式是 `(side_kp, side_kd, fwd_kp, fwd_kd)`；横向限幅分别为 `50/80`，前后限幅统一为 `30`。两轴斜率限制均为 `15`，D 低通为 `0.35`。当前前向 PD 已开启，旧说明中的 `(8,16,0,0)` 和“前向环关闭”均已过期。
- 物体紧贴推杆的车体系 y 标定为：主车网球/蓝沙包/红沙包 `12 cm`、白熊/棕熊 `13 cm`；从车五类均为 `9 cm`。就位距离为主车 `14/14/14/13/13 cm`、从车 `11/11/11/9/9 cm`。普通 PUSH 的 y 目标使用紧贴标定值；x 目标按槽位取符号，网球/白熊/棕熊为 `±2 cm`，两个沙包为 `0 cm`。基础速度内偏为主车 `2°/4°`、从车 `2°/3°`（网球/其他类）。从车 PUSH 球体修正由 `_PUSH_BALL_CORRECTION_ENABLE=0` 关闭，但 APPROACH / WAIT_READY 的球检测与 VDOCK 仍由 `_PUSH_BALL_SYNC_ENABLE=1` 使用。
- 主车目标类别槽连续不匹配当前目标 `800 ms` 后才进入丢目标处理；旋找最长 `3200 ms`，对车状态丢失确认 `2000 ms`。从车自己暂时看不到目标、但主车仍新鲜且处于 PUSH 时，会继续跟推。
- 主车完成判定必须同时满足：本次 PUSH 开始后相关轴收到过新视觉坐标修正，并且本车越过目标边 `6 cm`。边 1 为 `y>=236`，边 2 为 `x<=-6`，边 3 为 `x>=316`，边 4 为 `y<=-6`。
- 从车不凭自己的场地坐标独立扣数量；只在收到主车 `PUSH_DONE`，或看到主车从 PUSH 进入 RECOVER/RELOCALIZE/DONE 后，执行一次完成计数。
- 推送完成后记录完成数量和最近推送方向，进入 RECOVER。

PUSH 内保留两类斜向避障实现，当前主车总开关 `_PUSH_DIAG_ENABLE=1`，因此满足触发条件时会启动以下斜推，并向从车发送对应命令：

1. **cone/brick 动态距离避障**：cone 和 brick 完全共用参数和代码路径，主车检查本车与对车各自最新的 cone/brick 观测，观测最多保留 `3000 ms`；布局过滤开启时，先按目标边全部三个位置及两个相邻角点屏蔽未声明的类型。同一避让侧必须在 `2` 个不同的新观测时间戳中连续成立才允许锁存，主循环重复处理同一帧不会重复计数。障碍需位于主车前方 `-8～80 cm`、主车推送路线横向 `±40 cm`。以障碍与当前被推物体在横向轴上的坐标差决定左右，若绝对间距小于 `60 cm`，实际斜移距离为 `60-|差值|`，偏航 `35°`，最长 `3000 ms`。两侧同时有障碍或无法确定单侧时不启动斜推。
2. **其他货物避障**：与cone/brick共用同一侧连续 `2` 个新观测时间戳的入口确认；动作参数仍为偏航 `15°`、固定斜移 `20 cm`、最长 `1600 ms`。

斜移动作进行中不会因逐帧观测变化而反复改方向或距离；达到锁存距离或超时后结束。当前代码在每次 PUSH 更新中先提交斜推请求，再检查越界完成条件，因此斜推尚未走完时如果已经满足 PUSH 完成条件，仍会直接退出 PUSH；完成条件的优先级高于继续执行剩余斜移。

### 6.6 RECOVER

主车当前有效流程：

```text
BACK
  -> VIS_FIX（对应推出边的 X 或 Y 边线修正）
  -> YAW_FIX（黄线视觉航向精调并一次性校准 IMU yaw）
  -> SEARCH / RELOCALIZE
```

主车 BACK 以速度 `120` 后退，按锁定车尾方向的有向投影达到 `8 cm` 时正常进入 `VIS_FIX`；向外惯性滑行和横向漂移不计入，`1500 ms` 仅作为车体卡住或里程计异常时的超时保护。进入 `VIS_FIX` 后先原地转到对应的目标正交航向，IMU误差进入 `±4°` 时才清零样本计数、启动独立的 `800 ms` 修坐标计时，并以速度 `140` 后退。视觉坐标按距预期边界 `50 cm` 的范围判断；收到2个符合范围的新坐标帧或真正修坐标达到800 ms后结束。结束瞬间调用硬停车，绕过全局世界速度缓停斜坡，立即清零世界/车体平移目标并请求清空速度环积分，然后进入 `YAW_FIX`；不再检查融合坐标距离刚推出边界的距离。

主车 `YAW_FIX` 成功或 `1000 ms` 超时后不再立即进入下一模式，而是进入 `WAIT_FOLLOWER_FOLLOW` 并保持修正后的航向停车。普通任务中要求从车已进入 SEARCH 的 `TRANSLATE_FORM`；全部任务完成时要求从车在 RELOCALIZE 中看到主车、保持画面居中且距离合格后上报 `ready>=2`，不再要求固定航向或绕到指定槽位。该等待没有自动超时，确保从车已经真正进入跟随阶段后主车才离开。

`YAW_FIX` 使用现有 Frame2 中的绝对视觉 yaw。目标航向由刚推出的边确定：边 1 为 `0°`、边 2 为 `270°`、边 3 为 `90°`、边 4 为 `180°`。进入后先停车稳定 `120 ms`，只处理新收到的视觉帧：

- 视觉误差在 `±2°` 内属于死区，车辆保持当前角度；至少 1 个新视觉样本且从首个合格样本起保持至少 `100 ms` 后判定完成。完成判断只在新视觉帧到来时执行，因此首帧合格后仍需等待后续新帧触发时间检查。
- 误差大于 `2°`、不超过 `25°` 时才允许自转修正。视觉误差只决定旋转方向，不参与速度大小计算：视觉 yaw 偏大就减小世界 yaw，视觉 yaw 偏小就增大世界 yaw，固定速度为 `50°/s`。
- `YAW_FIX` 不再使用“视觉误差 → 目标角”的外层航向角 PID，而是通过 `base.request_yaw_rate()` 直接给定固定 yaw 角速度；底层陀螺角速度环仍保留，用于维持定速和在命令为 0 时停车。
- 误差超过 `±25°` 或视觉角无效时不采用该帧，保持当前角度等待下一帧。
- 稳定完成后调用 `base.correct_yaw(fix_yaw)`，把当前连续 yaw 的世界坐标基准一次性对齐到精确的 `0°/90°/180°/270°`，同时清除角度 PID 历史，之后 IMU 继续从新基准积分。
- `YAW_FIX` 最多等待 1000 ms；该时间包含入口的 `120 ms` 停车。超时只停止自转并保持当前航向，不强行写入 IMU yaw，避免用不可信视觉值校准。

从车当前有效流程：

```text
BACK -> TURN（转到槽位对应观察角） -> TRANSLATE（沿推送反方向平移找主车）
                                      -> SEARCH / RELOCALIZE
                                      └─ 2000 ms 未找到：停车留在 RECOVER
```

从车 BACK 与主车一样以速度 `120` 后退，并按锁定车尾方向的有向投影达到 `8 cm` 结束，`1500 ms` 仅作为超时保护；结束后先硬停车。从车随后以固定 `200°/s` 转到观察角，允许误差 `±7°`：原左槽取 `push_yaw+90°`，原右槽取 `push_yaw-90°`。转到位后锁住观察角，以速度 `100` 沿 `push_yaw+180°` 的世界方向平移回场内，同时持续识别主车；只有主车视觉帧不超过 `250 ms` 且相对 X 进入 `±10 cm`，才立即结束 RECOVER，按本地剩余数量切入 SEARCH 或 RELOCALIZE，并挂起一次不受普通 `500 ms` 周期限制的主车视觉反算坐标修正。平移 `2000 ms` 仍未满足条件则停车留在 RECOVER，不再采用旧的原地累计两圈找车方案。进入最终 RELOCALIZE 后仍需完成第二层轻量跟随握手，主车才开始自身重定位移动。

### 6.7 RELOCALIZE 与 DONE

主车：

- 先原地转到 `270°`，允许误差 `6°`；进入误差范围后不停车，以匀速世界合速度 `160` 前往预设点 `(50,50)`。到点容差为 X/Y 各 `15 cm`，穿过目标平面或运行满 `4000 ms` 也会结束，不使用位置环末端减速；
- PREMOVE 到位、越线或超时后不停车，直接以速度 `120` 向低 X 前进并进入 X 边线修正；要求 1 个新样本且 `x<60`，最长 `4000 ms`；
- X 修正成功后不停车，直接开始转到 `180°`；进入 `6°` 误差范围后立即以速度 `120` 向低 Y 前进。Y 修正要求 1 个新样本且 `y<60`，最长 `4000 ms`。如果 X 修正超时，会直接结束 RELOCALIZE，不再执行 Y 修正；
- 三段平移复用主车本地 cone/brick 障碍记忆：最近障碍小于 `50 cm` 时线性叠加最大 `150` 的世界 `-Y` 速度，不再根据运动方向或障碍左右选边；不使用从车障碍坐标。

从车：

- RELOCALIZE 跟随段使用独立的简化控制，不再复用 SEARCH ORBIT，也不锁 `180°`：视觉看到主车时用 face 控制保持主车在画面中心，并用径向平移保持 `30 cm` 距离；无线状态新鲜时叠加主车世界速度的 `1.1` 倍前馈，径向限幅 `120`、合速度上限 `240`；
- 从车在 RELOCALIZE 跟随主车、前往预设点和之后自身 X/Y 修正的所有平移阶段，使用与主车完全相同的本机 cone/brick 固定方向斥力：四槽、`40 cm`同物合并、`3000 ms`记忆、`50 cm`触发、最大速度`150`、方向固定为世界`-Y`；停车、原地找车和转向阶段不叠加斥力，也不使用另一台车上传的障碍坐标。
- 跟随段 `ready=2` 只要求主车视觉有效、滤波画面方位误差不超过 `6°`、距离误差不超过 `15 cm`、主车无线状态新鲜，并连续稳定 `50 ms`，完全不检查从车绝对航向。主车开头仍会停车等待这个轻量 ready，随后移动期间即使 ready 波动也不会重新停车；
- 暂时看不到主车但无线坐标仍新鲜时，从车用两车世界坐标估算方位和距离继续跟随并转头争取恢复视觉；视觉和无线参考同时失效时原地自转找车，连续 `1500 ms` 仍未恢复则启动与正常收尾相同的“前往预设点 → X/Y 修正”兜底；
- 从车在整个跟随段继续每 `500 ms` 最多一次利用“主车无线世界坐标 + 本机视觉相对坐标”修正自身 X/Y。主车处于 RELOCALIZE 的 X/Y 修正期间，从车始终继续保持跟车；收到主车新鲜的 DONE 后，从车锁存当时航向并解除跟随。若航向在 `0°～30°`，则锁住该航向以速度 `160` 沿世界 `+X` 开环移动，X 增加 `20 cm` 后结束；若航向在 `>30°～90°`，则以同样方式沿世界 `+Y` 移动，Y 增加 `40 cm` 后结束；其他航向跳过特殊脱离。两段均有 `1500 ms` 异常超时。之后统一转到 `270°`，以与主车完全相同的 PREMOVE 参数前往自己的预设点 `(70,90)`：合速度 `160`、X/Y 到点容差各 `15 cm`、最长 `4000 ms`，到点、越过目标平面或超时均结束该段，并继续使用本机 cone/brick 斥力。随后从车以速度 `140` 修 X，再转到 `180°` 以速度 `140` 修 Y，完成后进入 DONE。X/Y 各要求 1 个有效新样本，各直线修正最长 `5000 ms`，X 超时会直接结束并跳过 Y；
- 从车每次进入 SEARCH 或 RELOCALIZE 时清除“已看到主车”锁存；摄像头首次识别到主车后立即锁存，并通过 Frame3 `flags.bit3` 上报。当前主车 RECOVER 的最终放行直接检查从车 SEARCH 子状态或上述 RELOCALIZE ready，该标志仍用于表达视觉可见性和从车自身定位流程。

DONE 中两车都先用位置请求返回 `(25,-50)`，速度上限 `200`，X/Y 到点容差均为 `2 cm`，到点稳定 `300 ms` 后进入新增的双车展示任务。两车均先直接检查 `car`，看不到就以 `90°/s` 原地持续自转；找车没有超时退出条件，只要仍未看到对方就一直保持该动作。看到对方后解除固定角速度搜索和绝对航向锁定，用视觉 face 控制保持对方居中，并以目标距离 `26 cm`、径向 Kp `7`、径向限幅 `80`（过近向外限幅 `120`）、合速度限幅 `200` 建立相对队形，不使用无线速度前馈。

双车相对位置连续稳定 `200 ms` 后各自发送 `ready=6`；本车和对方都 ready 后，以相同方向、固定切向速度 `60` 相互绕行。每辆车只累计规定方向上的正向车头角增量，第一次达到或超过 `380°` 时立即硬停车，不减速、不精修、不反向纠正，并持续发送 `ready=7`。一车先完成后保持不动，另一车可继续围绕它完成自己的剩余角度。绕行中视觉 car 丢失或对方无线状态失效时立即停车、ready 清零并退回找车阶段，本轮累计角清零。

## 7. 底层运动、定位与实时调度

### 7.1 运动接口

任务层只应调用：

- `base.request_world(vx, vy, angle)`：世界坐标系速度；
- `base.request_yaw_rate(yaw_rate_dps)`：原地按固定世界 yaw 角速度旋转，绕过外层航向角 PID；
- `base.request_pos(tx, ty, speed, angle)`：世界坐标位置闭环；
- `base.request_hold(angle)`：停车并保持车头；
- `base.request_push(...)`：推送专用控制；
- `base.clear_face()` / 面向目标接口：退出视觉直接角速度控制。

`motion_step()` 消费最新请求，处理位置环、推送环、角度环以及世界系到车体系的转换。`car_omni()` 再把车体 X/Y/Z 分解为四轮目标速度。

### 7.2 定位

- 编码器通过四轮增量积分世界 X/Y，主从各有独立 `_MILEAGE_KX/_MILEAGE_KY` 标定值。
- IMU 名义周期 `_DELTA_T=0.01 s`，实际姿态积分优先使用相邻采样的 `ticks_us` 实测间隔；实测 `dt` 不在 `0.002～0.05 s` 时才回退到 `0.01 s`。yaw 主路径仍是陀螺积分。
- 加速度计仅在合加速度接近 `1 g`、误差不超过约 `0.03 g` 时参与 Roll/Pitch 修正，降低运动加速度污染。
- OpenART 黄线会发送绝对 yaw、X 或 Y。连续运行中的 `_vis_yaw_fix_en` 仍保持 `False`，视觉 yaw 不会在底层每帧直接覆盖车辆 yaw；主车只在 RECOVER 的 `YAW_FIX` 中显式读取 `_YawAngle_fix` 做闭环自转，并在稳定后调用一次 `base.correct_yaw()`。X/Y 会在 RECOVER、SEARCH 黄线补坐标、PUSH_SYNC、RELOCALIZE 等特定阶段按轴打开。
- Roll/Pitch 在接近零的小角度下每 4000 ms 更新持久零点，不影响 yaw。

### 7.3 定时器

- ticker1：1 ms，分频执行角度环、角速度环、电机控制、位置环和发送标志。
- ticker2：10 ms，读取 IMU/编码器并融合位姿。
- ticker3：3 ms，闭环处理无线收发；每 3 次（约 9 ms）解析一次摄像头串口；在非解析的那两拍里发送 Frame1。
- 主循环负责任务状态机、LCD、无线命令 TTL 检查和垃圾回收，不再发送任何串口帧。

Frame1 的发送已从主循环下沉到 ticker3。原来 `uart_send_pose()` 在主循环里执行，实际周期等于
`max(10 ms, 主循环周期)`，而主循环含 `task.update()`、LCD 和每轮一次的 `gc.collect()`，会被拉长到
15~40 ms；OpenART 用这个位姿做 `rel→world` 换算和黄线 wall 判定，位姿旧则结果直接偏。下沉后周期回到
`10 ms + 0~6 ms`。为避免同一个 3 ms ISR 里叠加两次阻塞写（Frame3 37 字节 1.6 ms + Frame1 17 字节 0.74 ms），
ticker1 里 Frame1 的置位相位由 `_COMM_FLAG_PHASE_TICK = 5` 与无线轮询错开半个周期。

无线采用主车发起、从车约 5 ms 后应答的半双工节奏；主车等回应超时为 60 ms。不要在中断回调中增加打印、动态大对象或耗时计算。

### 7.4 安全/辅助功能当前状态

- LCD 调试 `_DEBUG_LCD = 1`：当前开启，以 500 ms 周期刷新精简后的调试信息。
- 普通 cone 绕行点已整套删除；SEARCH SWEEP只用本机cone/brick相对坐标触发提前换行，STEP才对锁存障碍沿下一次反向SWEEP方向退让；横扫与 STEP 基速均为 `120`，最大退让速度为 `168`。主车RELOCALIZE使用`50 cm`触发、最大`150`且固定世界`-Y`的斥力。
- 倾角脱困及姿态反推 cone 已整套删除；Roll/Pitch 姿态估计和零点修正仍保留，视觉 cone/brick 数据以及 SEARCH/RELOCALIZE/PUSH 避障不受影响。
- PUSH 诊断斜推：主车 `_PUSH_DIAG_ENABLE = 1`，当前开启。

## 8. OpenART 视觉端

### 8.1 启动配置

- QVGA `320×240`，模型输入 `96×96`；
- UART12，230400 baud；
- 固定白平衡、增益、曝光，色阈值必须在这套固定曝光下标定；
- 优先用 `load_to_fb=True` 加载模型，失败则保留黄线/球检测但禁用 YOLO；
- 当前数据集保存 `SAVE_IMAGE_ENABLE=False`，正式任务不会向 `/sd/dataset/` 写 JPEG；需要采集时可临时开启，开启后每 `10` 帧保存一张质量 `95` 的 JPEG 并维护 `EPOCHNUM`，需留意 SD 写入对帧率和容量的影响；
- 当前 `DRAW_DEBUG=False`，不绘制调试框；
- 当前 `CAR_ID=1`，使用主车单应矩阵、屏幕原点 `(160,239)` 和 `rod_offset_cm=10.0`。从车应改为 `CAR_ID=2`，对应 `(155,239)` 和 `7.0 cm`。

### 8.2 每帧管线

1. 采图；
2. 若开黄线，做黄色 blob、射线取点、线段拟合，结合 IMU yaw 解算绝对 yaw 与 X/Y 边线距离；
3. 先发送一次“当前位姿 + 上一帧目标”，降低 YOLO 推理延迟；
4. 若开球识别，做紫/橙色 blob、形状门控或可选霍夫圆、α-β 时域跟踪和高度修正；
5. 若开模型，letterbox 后做 TFLite 检测，再按颜色细分 sandbag/teddy；
6. 用单应矩阵把目标落地点转换为车体系厘米坐标，再结合主控位姿得到世界坐标；
7. 按计数模式、剩余类别、主车自主选择或从车给定目标相对坐标筛选目标；从车锁定主车指定目标时，候选与主车下发目标的车体系相对 X/Y 差值必须分别落在 `±40 cm` 内；主车自由搜索只在 `60 cm` 内选最近目标，并要求同类、相邻位置 `30 cm` 内连续出现 2 个推理帧后发布；
8. 发送 Frame2，然后垃圾回收。

主控通过 Frame1 动态控制 `LINE_ENABLE`、`MODEL_ENABLE`、`BALL_ENABLE`。因此 `openart.py` 顶部的初值只影响收到第一帧命令之前。

## 9. 串口协议

三种帧均以 `0xAA 0x55` 开头，并使用多项式 `0x31` 的 CRC8。16 位一般以 0.1 为精度；Frame3 的紧凑坐标为 0.5 cm 精度。改协议必须同时修改发送端、接收端、长度检查和本文。

### 9.1 Frame1：RT1021 → OpenART，类型 8，固定 17 字节

三个视觉开关、数量模式、`0～7` 总剩余数和物体映射边模式合并在一个控制字节中。帧内没有长度字节。

| 字节 | 含义 |
| --- | --- |
| 0..1 | `AA 55` |
| 2 | 类型 `8` |
| 3..4 | 本车 yaw ×10，有符号 16 位 |
| 5..6 | 本车 X ×10 |
| 7..8 | 本车 Y ×10 |
| 9 | control：bit0 黄线、bit1 模型、bit2 标记球、bit3 视觉数量模式（0按剩余类别 mask；1只看总数）、bit4～6 总剩余数、bit7 保留并固定为0 |
| 10 | 当前约束目标类别 `sel_id`，0 表示自由选择 |
| 11 | 1～5 类剩余目标 bit mask |
| 12..13 | 当前目标相对 X ×10；无效为 999 |
| 14..15 | 当前目标相对 Y ×10；无效为 999 |
| 16 | CRC8，覆盖 2..15 |

OpenART 从字节 9 的 bit3 取得视觉数量模式，从 bit4～6 取得总剩余数，从 bit7 取得物体映射边模式。视觉模式 0 按 bit mask 过滤类别，覆盖控制器的类别组模式 2 和当前五类分别计数模式 3；视觉模式 1 中只要总剩余数大于 0，1～5 类都可识别，同一类别可连续搬运。模式 1 的单类跟踪容量最多为 `min(总剩余数,5)`。发送端会把总剩余数限制在 `0～7`。

### 9.2 Frame2：OpenART → RT1021，类型 7，固定 40 字节

当前帧不再发送槽位数。七个槽的位置和语义固定，黄线矩形中心 x 放在帧尾：

| 字节 | 含义 |
| --- | --- |
| 0..1 | `AA 55` |
| 2 | 类型 `7` |
| 3..4 | 当前图像解算的视觉 yaw ×10；无效为 999 |
| 5..6 | 推杆/车体参考 X ×10 |
| 7..8 | 推杆/车体参考 Y ×10 |
| 9..12 | slot0：普通任务目标 0 |
| 13..16 | slot1：普通任务目标 1 |
| 17..20 | slot2：另一台车 |
| 21..24 | slot3：左/紫色标记球 |
| 25..28 | slot4：右/橙色标记球 |
| 29..32 | slot5：cone |
| 33..36 | slot6：brick |
| 37..38 | 黄色线矩形中心原始像素 x ×10；无效为 999 |
| 39 | CRC8，覆盖 2..38 |

每个槽固定 4 字节：`[rel_x int8 cm, rel_y int8 cm, class_id, track_id]`；空槽 `class_id=255`。主车自由选物连续 2 帧确认的首帧中，slot0 使用 `class_id=255、track_id=254` 表示“有候选、尚未发布”。下位机把 cone 和 brick 分别保存到独立缓存。

`base.py` 仍保留旧动态长度协议的接收兼容：

- 类型 `2`：字节 9 为槽位数，不带黄线中心；
- 类型 `4`：字节 9 为槽位数，槽后带黄线中心。

当前工作区 `openart.py` 实际只发送类型 `7`；新旧摄像头固件不能只靠总长度猜测，部署时应确认类型一致。

### 9.3 Frame3 v4：双车无线，类型 6，固定 37 字节

旧类型 `3/4/5` 只计数、不解析，用于暴露两车固件协议不一致。当前世界 X/Y 速度已从 `int8` 改为 `int16 ×10`，可覆盖 SEARCH、PUSH、RELOCALIZE 等状态超过 127 的速度。

| 字节 | 含义 |
| --- | --- |
| 0..1 | `AA 55` |
| 2 | 协议/类型 `6` |
| 3 | 帧序号，8 位循环；接收端累计推测丢帧 |
| 4..5 | 本车 yaw ×10，无符号 0..3599 |
| 6..8 | 本车 X/Y，各 12 位有符号，0.5 cm 精度 |
| 9..11 | 当前目标 X/Y，格式同上 |
| 12..14 | 本车当前视觉 cone X/Y，格式同上 |
| 15 | fresh flags：bit0 目标有效，bit1 cone 有效，bit2 brick 有效，bit3 本车在当前 SEARCH/RELOCALIZE 阶段已通过视觉看到对方；bit4～5 为 RECOVER 后第一次 SWEEP/Forward 侧向阵型相对 SEARCH 航向的方向（0无效、1左、2右、3保留）；bit6～7 保留 |
| 16 | 高 5 位 `self_mode`，低 3 位 `self_ready` |
| 17 | `self_sub` |
| 18 | 高 4 位目标边，低 4 位目标类别 |
| 19 | 高 5 位命令序号，低 3 位命令子类型 |
| 20..21 | approach 命令 ×10 |
| 22..23 | route 命令 ×10 |
| 24..25 | 从车目标 yaw/绕向命令 ×10 |
| 26..27 | route 观测轴 ×10 |
| 28..29 | 世界 X 速度，`int16 ×10` |
| 30..31 | 世界 Y 速度，`int16 ×10` |
| 32 | PUSH 横向保持速度 ×2，int8，即 0.5 分辨率 |
| 33..35 | 本车当前视觉 brick X/Y，各 12 位有符号，0.5 cm 精度 |
| 36 | CRC8，覆盖 2..35 |

Frame3 语义注意点：

- 主车发送命令；从车在相同命令字段回传最近收到的序号/子命令作为 ACK；
- 从车在 SEARCH/RELOCALIZE 阶段第一次看到主车后锁存 `flags.bit3`；主车只在无线状态新鲜且从车模式匹配时采用该标志；
- `flags.bit4~5` 仅由主车在 SEARCH 中发送，从车回包和非 SEARCH 模式固定为0；有效期从正常 RECOVER 后第一次 S3 持续到第一次 Forward 完成，无 Forward 时到第一次 Sweep 结束；无线命令 TTL 失效时接收端立即清零，避免旧方向跨状态残留；
- 无线超过 `1000 ms` 没有新帧会清除命令类字段，防止旧命令继续动作；
- cone/brick 字段只发送本车当前视觉观测，不发送本地维护表；
- 主车 PUSH 时把本车和对车的 cone/brick 合并为障碍候选，brick 完全复用 cone 参数；
- `base.py` 分别只保存当前最新的 cone 和 brick 观测，均在 `3000 ms` 后失效；主车 SEARCH/RELOCALIZE 与从车 RELOCALIZE 再各自维护四槽障碍记忆，这两层缓存语义不同；
- 无线为主车请求、从车应答：从车约延迟 `5 ms` 回帧，主车等待回应最长 `60 ms`。

## 11. 已知问题与风险

以下按“当前源码 + 历史记录”归纳。历史问题可能已缓解但未形成实车关闭结论，处理前应复测。

### OpenART 版本差异提示

- 新版 `base.py` 可接收旧类型 `2/4` 动态槽帧和当前类型 `7` 固定 40 字节帧；当前工作区 `openart.py` 发送类型 `7`。
- 黄线中心、brick 和无槽位数字段只有在烧录当前 OpenART 固件后才会按新布局出现；上下位机应成套更新。

### 高优先级实车问题

- PUSH 中物体、尤其沙包可能从双车 V 字阵列中掉出；需区分视觉参考、两车速度差、V 张开和推送方向不一致。当前障碍斜推已开启，复现问题时还应对比普通直推与斜推阶段。
- 从车斜向推送曾长期表现为前进速度比主车慢；当前主从基础推送速度均为 `150`，PUSH 斜推总开关开启。仍需实车确认机械差异、斜推分量以及物体横向/前向 PD 叠加后的真实速度。
- 标记球仍有误识别风险。现有颜色、形状、距离和跳变门控并不能保证首次不会锁错；若从车向异常方向修正，先检查球槽识别和参考点。
- 当前固定球参考五类统一为 `(9,13,-11,13)`；四元组依次是左槽位 `(x,y)`、右槽位 `(x,y)`。改前按目标分两组（网球/白熊/棕熊 `(8,19,-10,16)`，蓝沙包/红沙包 `(9,20,-10,16)`），本次重标后不再区分类别，且 V 字比原来更紧（前向 19/16 → 13）。

### 定位与 IMU

- yaw 日常运行仍依赖陀螺积分，仅在主车 RECOVER 的 `YAW_FIX` 成功后做一次视觉正交航向校准；当前已改用实测 `dt`，但两次校准之间仍会受陀螺刻度因子、采样抖动、静止判据和温漂影响。
- 7.22 已加入 Roll/Pitch 小角度周期零点，但这不修复 yaw 漂移。
- 里程计 KX/KY 已按 7.22 实测写入主从不同系数，换轮胎、底盘或编码器后需要重新标定。

### 功能开关与未完成项

- 普通cone绕行点已经删除；SEARCH使用“SWEEP相对坐标门触发、STEP锁存障碍退让”，横扫和换行前进基速均为 `120`，最大退让为基速的 `1.4` 倍即 `168`；PUSH双车cone/brick斜推与RELOCALIZE本机cone/brick固定世界`-Y`斥力也已启用，几套机制的适用范围不要混淆。
- cone 固定锚点修坐标（`config._CONE_WORLD_POINTS` + `base.cone_anchor_position_fix`）已因主车 RAM 不足移除。两个锚点原本都是 `(999,999)`，功能从未真正生效。需要时按《已移除代码备份.md》的 B2/B2b/B2c/B2d 恢复。
- RELOCALIZE 主车 X 边线修正一旦超时会直接结束整个重定位，跳过 Y 修正；这是当前代码真实行为，实车上应重点观察。
- 当前 PUSH 斜推执行期间，边界完成条件仍可立即结束 PUSH，不会等待斜移距离执行完；若要求“避障必须完整走完”，需要重新定义优先级。
- SEARCH 异常出口、无线抖动、目标误检和视觉短丢仍应做系统性实车覆盖。
- `SAVE_IMAGE_ENABLE` 当前为 `False`；临时打开数据集保存时应确认 SD 容量和写入开销，并在正式运行前重新关闭。
- RECOVER 速度、APPROACH 半径/PID 和通信字段整理仍是待优化方向。

## 13. 推荐开发与验证方式

一次只验证一个控制层，避免把视觉、编队、障碍和 PID 问题混在一起：

1. 先确认目标问题属于主控、无线、OpenART 还是机械；
2. 搜索参数定义，同时搜索所有引用，确认哪组参数真的进入调用链；
3. 修改根目录源文件，不动生成目录；
4. 对主车和从车同名参数分别检查，不能假设两边自动共享；
5. 运行 `build.bat`，确认完整显示 `Build complete.`；
6. 核对两个角色配置和生成时间；
7. 先台架验证串口、LCD、目标槽位和状态切换，再低速实车；
8. 记录模式、子状态、目标 ID/边、两车位姿、ready、视觉相对坐标、无线新鲜度和电机反馈；
9. 实车确认后同步更新本文的“当前配置/已知问题”，并在新的日期修改记录中保留过程细节。

对 PUSH 调参，先临时排除斜推/路线绕障，再分别观察：主车物体环、从车 V 张开通道、从车推送轴追赶、世界横向锁定和基础速度。不要一次同时改多组增益。
