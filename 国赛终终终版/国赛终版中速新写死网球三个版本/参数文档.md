# 双车协同搬运工程参数文档

> 基于 `8.18/base.py`、`8.18/config.py`、`8.18/task_leader.py`、`8.18/task_follow.py` 当前源码整理。数值以源码为准，历史说明文档中的旧值不作为运行参数。
>
> 速度的单位沿用底盘控制量（代码未换算为 cm/s 的物理单位）；距离为 cm，角度为度，时间为 ms，角速度为度/秒。`999.0/999.9` 通常表示无效坐标、无效角度或无协同命令。

## 1. 工程与状态机总览

运行入口是 `main.py -> base.main_init() -> base.loop()`。`base.py` 负责 IMU、编码器、OpenART/无线通信、运动请求和底层 PID；任务层只调用 `request_world/request_pos/request_hold/request_yaw_rate/request_push`。

主从共用的大状态编号及正常流程：

| 编号 | 状态 | 正常作用 | 正常后继 |
|---:|---|---|---|
| 1 | `_MODE_BOOT_SYNC` (`BOOT_SYNC`) | 摄像头、无线握手，开局横移 | `_MODE_SEARCH` |
| 12 | `_MODE_SEARCH` (`SEARCH`) | 主车蛇形找目标；从车跟随主车编队 | 发现目标 -> `_MODE_APPROACH`；无目标超时 -> `_MODE_RELOCALIZE` |
| 13 | `_MODE_APPROACH` (`APPROACH`) | 两车绕到目标两侧并贴靠 | 就位 -> `_MODE_WAIT_READY`；丢目标 -> `_MODE_SEARCH` |
| 14 | `_MODE_WAIT_READY` (`WAIT_READY`) | 保持就位、检查目标姿态和推送走廊 | 两车 ready -> `_MODE_PUSH_SYNC`；姿态坏太久 -> `_MODE_APPROACH` |
| 15 | `_MODE_PUSH_SYNC` (`PUSH_SYNC`) | 双车同步推送、斜避障碍、路线横推 | 推送完成 -> `_MODE_RECOVER`；严重丢车/丢目标 -> `_MODE_APPROACH` 或 `_MODE_SEARCH` |
| 16 | `_MODE_RECOVER` (`RECOVER`) | 推完后退出目标区、恢复搜索编队 | 有剩余目标 -> `_MODE_SEARCH`；全部完成 -> `_MODE_RELOCALIZE` |
| 19 | `_MODE_RELOCALIZE` (`RELOCALIZE`) | 黄线/预设点重定位，并恢复编队 | 完成 -> `_MODE_DONE` |
| 17 | `_MODE_DONE` (`DONE`) | 返回终点并停稳（主车额外自转一圈） | 保持结束 |

## 3. 状态一：BOOT_SYNC

### 3.1 进入和退出条件

1. 初始模式固定为 `_MODE_BOOT_SYNC=1`，不经过普通 `enter_mode()`。
2. 摄像头收到过有效帧（`_cam_rx_last_ms != 0`）后本车 ready 置 1；主车还要求从车时间戳新鲜且 ready≥1。
3. 无线握手使用 `_BOOT_OTHER_FRESH_MS=800` ms；摄像头提示蜂鸣 `_BOOT_BEEP_CAM_MS=120` ms，无线提示 `_BOOT_BEEP_WIRELESS_MS=400` ms，间隔 `_BOOT_BEEP_GAP_MS=250` ms。
4. 主车发送 `_CMD_SUB_BOOT_START=5`，从车收到主车启动信号后开始横移。
5. 主车 `Position_Y - _boot_lateral_y0 >= _BOOT_LATERAL_DISTANCE_LEADER_CM`，从车相应使用 `_BOOT_LATERAL_DISTANCE_FOLLOWER_CM`，达到后切入 `SEARCH`。

### 3.2 运动参数

| 变量 | 值 | 作用 |
|---|---:|---|
| `_BOOT_LATERAL_SPEED` | `160` | 世界 +Y 横移 |
| `_BOOT_LONGITUDINAL_SPEED` | `20` | 主车前进/从车后退的间距分量 |
| `_BOOT_LATERAL_DISTANCE_LEADER_CM` | `60` | 主车横移退出距离 |
| `_BOOT_LATERAL_DISTANCE_FOLLOWER_CM` | `60` | 从车横移退出距离 |
| `_BOOT_OTHER_FRESH_MS` | `800` | 从车 BOOT ready 新鲜窗口 |
| `_BOOT_BEEP_CAM_MS` | `120` | 摄像头正常提示 |
| `_BOOT_BEEP_WIRELESS_MS` | `400` | 无线正常提示 |

## 12. 调参优先级

1. 先确认 `_MILEAGE_KX/KY` 和 `_INIT_YAW`，因为 BOOT 距离、SEARCH 边界、PUSH 完成和 RELOCALIZE 都依赖里程计。
2. 速度优先调状态层基座速度（SEARCH、APPROACH、PUSH、RECOVER、RELOCALIZE），再调对应视觉 PID 限幅；不要先改底层电机 PID。
3. 普通 PUSH 基座速度当前均为 `140`。路线横推 `_PUSH_ROUTE_SPEED` 的源码注释写着“两车基座速度相同”，但实际值是主车 `80`、从车 `120`，属于代码与注释不一致；调参前应通过实车日志确认哪个值才是预期，不能直接把这一差异视为已验证设计。
4. 改变贴靠几何时，必须同时检查 `_CLOSE_DIST_*_BY_OBJ`、`_PUSH_REF_REL_*_BY_OBJ`、VDOCK 参考和 `_APPROACH_LOCK_DEG`。
5. 改变状态切换速度或距离时，必须同步检查对应 timeout、EPS、stable/require 参数，否则会出现提前切换、反复回退或超时兜底。

## 13. 当前源码中需要注意的不一致

1. `task_leader.py` 的 `_RELOC_PREMOVE_SPEED` 注释写“后续 X/Y 速度为 120”，实际 `_RELOC_SPEED=140`；本文按执行常量记录为 140。
2. 主车 RELOCALIZE 定义并实现了 PREMOVE，但正常 `FORMATION_WAIT` 成功分支直接进入 `X_TURN`，所以主车 PREMOVE 参数当前是保留但未走到的参数。
3. PUSH_ROUTE 附近注释要求两车 `_PUSH_ROUTE_SPEED` 相同，实际主车为 80、从车为 120；本文保留实际值并明确标注风险。
